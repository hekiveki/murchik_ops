# MurchikOps - Мяу! Я Мурчик, работа кипит - прямо под лапами.

**CatOps** — учебный DevOps-проект, объединяющий виртуального питомца в стиле Tamagotchi и практики Chaos Engineering. Мурчик создаёт контролируемые сбои тестового сервиса, а система обнаруживает недоступность приложения, выполняет восстановление и проверяет его работоспособность.

Этот проект посвящен моему любимому проказливому коту Мурчику, которому совсем скоро, а именно 3 сентября исполнится год.

Проект демонстрирует базовые подходы к контейнеризации, мониторингу состояния сервиса и автоматизации восстановления после сбоя.

## Возможности

- Интерактивный терминальный интерфейс с виртуальным котом Мурчиком.
- Запуск приложения в изолированном Docker-контейнере с помощью Docker Compose.
- Проверка состояния приложения через HTTP health check.
- Имитация отказа сервиса в контролируемой тестовой среде.
- Автоматизированный сценарий восстановления контейнера.
- Проверка доступности сервиса после восстановления.
- Система опыта (XP), уровней и достижений.
- Журнал инцидентов с результатами проверок и восстановления.

## Стек

## Технические требования

Для запуска необходимы:

- Python 3.10 или новее.
- Установленный и запущенный Docker Engine или Docker Desktop.
- Docker Compose V2.
- Доступ к интернету при первой сборке образа и установке зависимостей.

## Установка и запуск

### 1. Создание виртуального окружения

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Запуск CatOps

```bash
python catops.py
```

При запуске приложение соберёт Docker-образ и поднимет тестовый сервис.

## Как пользоваться

После запуска откроется интерактивное меню.

| Команда | Действие |
|---|---|
| `1` | Проверить состояние сервиса |
| `2` | Смоделировать сбой и запустить восстановление |
| `3` | Просмотреть журнал инцидентов |
| `4` | Остановить тестовое окружение и выйти |

### Сценарий демонстрации

1. Запустите CatOps и убедитесь, что сервис доступен.
2. Выберите пункт `2`, чтобы смоделировать отказ приложения.
3. Дождитесь выполнения сценария восстановления.
4. Убедитесь, что проверка `/health` снова проходит успешно.
5. Повторите сценарий, чтобы заработать опыт и открыть достижения.

## Проверка работоспособности

После запуска сервиса HTTP-эндпоинт проверки здоровья доступен по адресу:

```text
http://127.0.0.1:8080/health
```

Проверить ответ можно командой:

```bash
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ:

```json
{
  "status": "healthy"
}
```

При успешной проверке сервис возвращает HTTP `200 OK`.

## Остановка окружения

Выберите пункт `4` в меню MurchikOps. Приложение выполнит команду остановки тестового окружения через Docker Compose.

## Безопасность

CatOps предназначен для локального обучения и демонстрации сценариев отказа.

- Сбои моделируются только в тестовом Docker-окружении.
- Приложение не требует доступа к production-инфраструктуре.
- Перед использованием подобных механизмов в реальной среде необходимо предусмотреть ограничения прав, контроль целевых ресурсов, журналирование и защиту от случайного воздействия на рабочие сервисы.

**Не запускайте сценарии моделирования отказов на production-системах.**
